# Реліз 2.1.208 — 2026-07-28

## Нові можливості

- **Screen reader mode** — режим з простим текстовим виводом для користувачів screen reader. Увімкнути через `claude --ax-screen-reader`, `CLAUDE_AX_SCREEN_READER=1`, або `"axScreenReader": true` в settings.
- **`vimInsertModeRemaps`** — налаштування для мапування two-key insert-mode послідовностей (напр. `jj` → Escape) у vim mode.
- **`CLAUDE_CODE_PROCESS_WRAPPER`** — корпоративний launcher: кожне self-spawn Claude Code запускається через обов'язковий wrapper executable.
- **Mouse-click support** для multi-select меню та рядків "Other" у fullscreen-режимі.

## Виправлення

- Швидкий режим відновлюється автоматично при поверненні до моделі що його підтримує (раніше залишався вимкненим)
- Відповіді фоновому агенту зберігаються при невдалій доставці та доставляються при restart сесії
- Attach до background сесії більше не падає після update що замінив binary
- Контекстне вікно більше не скидається до 200k після CLI auto-update
- Краш supervised/background сесій при HTTP/2 GOAWAY під час активних запитів
- Обривання stream-json/JSON виводу при piping великих відповідей з `claude -p`
- `CLAUDE_CODE_MAX_OUTPUT_TOKENS` тощо мовчазно використовували mantissa наукової нотації (`1e6` → `1`)
- Великі markdown таблиці (>200 рядків) більше не зависають — показують перші 200 з "… N more rows"
- Edit tool на файлах змінених після читання (якщо текст збігається)
- Read (порожні файли), Grep (некоректний regex, count пагінація), Glob (null byte)
- Помилки `apiKeyHelper` скрипта видно за 3 спроби замість ~10 мовчазних retry з 401
- Bedrock streaming: оманлива "Truncated event message" при проксі що змінює content-type
- `/upgrade` показував login flow замість upgrade URL
- stream-json вбивав сесію на порожніх CRLF від Windows-style SDK hosts
- stream-json зависав при non-string `set_model` payload
- Сиротілі background tasks при resume згортаються в одне повідомлення
- Remote Control clients на terminal-hosted session не бачили background agents/workflow progress
- Agent tool з порожнім `tools` повертає зрозумілу помилку
- `/usage` показував застарілі bars; `/mcp` не перкласифікував placeholder-сервери
- "Change directory" у SDK hosts падав з "A turn is in progress" на idle сесіях з background task
- Діалог збереження workflow показував `~/.claude/workflows/` замість `CLAUDE_CONFIG_DIR`
- `/release-notes` вставляв весь changelog у контекст моделі при "Show all"
- Витоки пам'яті: вставлені зображення, MCP stdio stderr (до 64 MB/сервер), LSP документи (тепер LRU 50), async hook output, великі tool-result payloads, довгі рядки при offset/limit читанні
- Сповільнення за хід при багатьох permission rules
- `/install-github-app` та `/mcp` більше не відкриваються в background сесіях
- MCP сервери з порожнім URL показуються як "not configured"
- Bedrock auth AWS SSO з sso_ck region (регресія 2.1.207)
- `/upgrade`, `/release-notes`, `/mcp` поведінка

## Важливі зміни

- Завершені background агенти залишаються в `/tasks` до очищення
- Ctrl+X в agent view видаляє лише worktrees з перейменованими гілками, не чіпає unpushed commits
- Катастрофічні видалення (`rm -rf ~`) в командах з `$(…)`/backticks/`<(…)` тепер запитують підтвердження в plan/auto mode
- Fable 5 usage-credits consent починає з фокусом на опції відмови
- Старіший daemon не перезапускає workers від новішої версії

## Покращення продуктивності

- Кешування tool-pool знижує CPU-навантаження за tool-call при багатьох MCP інструментах
- Кеш читання файлів обмежено до 16 MB (замість 1000 повних файлів)
- Розмір транскрипту зменшено до 79x у edit-heavy сесіях; обмежено checkpoint disk usage
- Зменшено пам'ять при resume сесій з background agents/forks
- Task list оновлення більше не перемальовує весь UI
